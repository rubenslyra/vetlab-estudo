1. Visão Geral da Arquitetura

Arquitetura em camadas com dependência apontando para dentro (Clean Architecture simplificada).

VET-Lab.Api (entry point — endpoints via Extensions) ↓ depende de VET-Lab.Application (serviços = "casos de uso", DTOs, interfaces de repositório) ↓ depende de VET-Lab.Domain (aggregates, entidades, value objects, regras de negócio, enums) ↑ implementado por VET-Lab.Infrastructure (EF Core, repositories concretos, DbContexts, Identity) // Dois contextos de banco, duas conexões, dois schemas lógicos no mesmo Postgres.

"Aqui eu uso o jargão 'caso de uso', mas na prática, na camada Application, os casos de uso são implementados como serviços — classes que orquestram agregados, repositórios e mapeamento. Cada método de serviço é um caso de uso. Poderia ser uma classe por caso de uso (padrão Request/Handler), mas para este tamanho, serviço por agregado basta."

3. Requisitos Funcionais & Não Funcionais

Funcionais (RF)
  • RF-01: Veterinário cria solicitação de exame (POST)
  • RF-02: Consultar solicitação por ID (GET) — retorna status
  • RF-03: Listar solicitações com filtro por status (GET)
  • RF-04: Laboratório atualiza status (PATCH) — com justificativa se REJEITADO
  • RF-05: Bioinformática registra laudo final → CONCLUIDO
  • RF-06: Autenticação de usuários (veterinário, técnico, bioinformata)
  • RF-07: Validação de CRMV e tipos de amostra/exame permitidos
Não Funcionais (RNF)
  • RNF-01: PostgreSQL em Docker (porta 5432), schemas separados
  • RNF-02: ASP.NET Core Identity para auth (schema próprio)
  • RNF-03: Resposta < 200ms em consulta por ID (índices)
  • RNF-04: Code-first com EF Core Migrations
  • RNF-05: Tratamento global de erros (ProblemDetails RFC 7807)
  • RNF-06: Preparado para CQRS/Event Sourcing (sem acoplamento)
  • RNF-07: API REST com JSON, códigos HTTP padronizados

5. Banco de Dados — Schemas & Duas Conexões

O PostgreSQL permite schemas lógicos dentro de um mesmo banco. Usamos isso para isolar o domínio de autenticação do domínio de produto — sem o overhead de duas instâncias, e com a vantagem de poder migrar para bancos separados no futuro (passo natural do CQRS).

SQL — criação dos schemas (executar uma vez)
-- Conectado em vetlab_db
CREATE SCHEMA IF NOT EXISTS auth;      -- tabelas do ASP.NET Identity
CREATE SCHEMA IF NOT EXISTS produto;   -- tabelas do negócio (solicitações, amostras)

-- Opcional: garantir search path
ALTER DATABASE vetlab_db SET search_path TO public;

-- Índice para performance na consulta por status (milhares de dados depois)
CREATE INDEX IF NOT EXISTS idx_solicitacao_status ON produto.solicitacoes_exame (status);
CREATE INDEX IF NOT EXISTS idx_solicitacao_veterinario ON produto.solicitacoes_exame (crmv);
CREATE INDEX IF NOT EXISTS idx_solicitacao_data ON produto.solicitacoes_exame (data_criacao DESC);
Infrastructure/Contexts/ProdutoDbContext.cs
using Microsoft.EntityFrameworkCore;
using VetLab.Domain.Aggregates.SolicitacaoExame;

namespace VetLab.Infrastructure.Contexts;

public class ProdutoDbContext : DbContext
{
    public ProdutoDbContext(DbContextOptions<ProdutoDbContext> options) : base(options) { }

    public DbSet<SolicitacaoExame> SolicitacoesExame => Set<SolicitacaoExame>();
    public DbSet<Amostra> Amostras => Set<Amostra>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // Tudo vai para o schema 'produto'
        modelBuilder.HasDefaultSchema("produto");
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(ProdutoDbContext).Assembly);
        base.OnModelCreating(modelBuilder);
    }
}
Infrastructure/Contexts/AuthDbContext.cs — Identity
using Microsoft.AspNetCore.Identity.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore;

namespace VetLab.Infrastructure.Contexts;

// IdentityUser padrão — pode estender com dados do veterinário (CRMV, etc.)
public class AuthDbContext : IdentityDbContext
{
    public AuthDbContext(DbContextOptions<AuthDbContext> options) : base(options) { }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.HasDefaultSchema("auth");
        base.OnModelCreating(modelBuilder); // importante: Identity cria suas tabelas
    }
}

"Veja o ponto chave: dois DbContexts, duas connection strings, dois schemas, um único Postgres. A connection string já leva o SearchPath. Isso é uma vantagem do PostgreSQL que eu cito — no MySQL/SQL Server a história é outra. E quando o sistema crescer e eu quiser separar escrita de leitura (CQRS), já tenho os contextos separados — é só apontar um para outra instância."

using VetLab.Domain.Exceptions;
using VetLab.Domain.ValueObjects;

namespace VetLab.Domain.Aggregates.SolicitacaoExame;

public class SolicitacaoExame
{
    public Guid Id { get; private set; }
    public string NomeVeterinario { get; private set; }
    public Crmv Crmv { get; private set; }              // value object
    public string NomeAnimal { get; private set; }
    public string Especie { get; private set; }
    public string Sintomas { get; private set; }
    public string SuspeitaClinica { get; private set; }
    public TipoAmostra TipoAmostra { get; private set; }
    public TipoExame TipoExame { get; private set; }
    public string? InstrucoesColeta { get; private set; }
    public StatusSolicitacao Status { get; private set; }
    public string? JustificativaRejeicao { get; private set; }
    public DateTime DataCriacao { get; private set; }
    public DateTime? DataAtualizacao { get; private set; }

    // EF Core precisa de um ctor vazio (protected)
    protected SolicitacaoExame() { }

    // Construtor de criação — garante invariantes
    public SolicitacaoExame(string nomeVeterinario, Crmv crmv, string nomeAnimal,
        string especie, string sintomas, string suspeitaClinica,
        TipoAmostra tipoAmostra, TipoExame tipoExame, string? instrucoesColeta)
    {
        if (string.IsNullOrWhiteSpace(nomeVeterinario))
            throw new DomainException("Nome do veterinário é obrigatório.");
        if (string.IsNullOrWhiteSpace(nomeAnimal))
            throw new DomainException("Nome do animal é obrigatório.");
        if (string.IsNullOrWhiteSpace(sintomas))
            throw new DomainException("Sintomas devem ser descritos.");

        Id = Guid.NewGuid();
        NomeVeterinario = nomeVeterinario.Trim();
        Crmv = crmv;
        NomeAnimal = nomeAnimal.Trim();
        Especie = especie.Trim();
        Sintomas = sintomas.Trim();
        SuspeitaClinica = suspeitaClinica.Trim();
        TipoAmostra = tipoAmostra;
        TipoExame = tipoExame;
        InstrucoesColeta = instrucoesColeta;
        Status = StatusSolicitacao.CRIADO;
        DataCriacao = DateTime.UtcNow;
    }

    // Transições de estado controladas — regra de negócio no domínio
    public void IniciarProcessamento()
    {
        if (Status != StatusSolicitacao.CRIADO)
            throw new DomainException($"Só é possível processar uma solicitação CRIADA. Status atual: {Status}");
        Status = StatusSolicitacao.EM_PROCESSAMENTO;
        DataAtualizacao = DateTime.UtcNow;
    }

    public void EnviarParaAnalise()
    {
        if (Status != StatusSolicitacao.EM_PROCESSAMENTO)
            throw new DomainException($"Só é possível enviar para análise a partir de EM_PROCESSAMENTO. Atual: {Status}");
        Status = StatusSolicitacao.EM_ANALISE;
        DataAtualizacao = DateTime.UtcNow;
    }

    public void Concluir(string laudo)
    {
        if (Status != StatusSolicitacao.EM_ANALISE)
            throw new DomainException($"Só é possível concluir uma análise EM_ANALISE. Atual: {Status}");
        if (string.IsNullOrWhiteSpace(laudo))
            throw new DomainException("Laudo final é obrigatório para concluir.");
        Status = StatusSolicitacao.CONCLUIDO;
        DataAtualizacao = DateTime.UtcNow;
    }

    public void Rejeitar(string justificativa)
    {
        if (Status == StatusSolicitacao.CONCLUIDO)
            throw new DomainException("Uma solicitação concluída não pode ser rejeitada.");
        if (string.IsNullOrWhiteSpace(justificativa))
            throw new DomainException("Justificativa é obrigatória ao rejeitar uma solicitação.");
        Status = StatusSolicitacao.REJEITADO;
        JustificativaRejeicao = justificativa.Trim();
        DataAtualizacao = DateTime.UtcNow;
    }
}
Domain/ValueObjects/Crmv.cs + DomainException.cs
// Value Object — imutável, validado na construção, comparado por valor
namespace VetLab.Domain.ValueObjects;

public record Crmv
{
    public string Valor { get; }

    public Crmv(string valor)
    {
        if (string.IsNullOrWhiteSpace(valor))
            throw new DomainException("CRMV é obrigatório.");
        // Formato esperado: UF-12345 (ex: MG-12345)
        if (!System.Text.RegularExpressions.Regex.IsMatch(valor.Trim(), @"^[A-Z]{2}-\d{4,6}$"))
            throw new DomainException($"CRMV '{valor}' inválido. Formato esperado: UF-12345.");
        Valor = valor.Trim().ToUpper();
    }

    public override string ToString() => Valor;
    public static implicit operator string(Crmv c) => c.Valor;
}

// ---- Domain/Exceptions/DomainException.cs ----
namespace VetLab.Domain.Exceptions;

public class DomainException : Exception
{
    public DomainException(string mensagem) : base(mensagem) { }
}

"Aqui o agregado é a estrela. Reparem: não há setters públicos. O status só muda através de métodos que sabem qual transição é válida. Isso é regra de negócio no lugar certo — o domínio. Se amanhã eu quiser Event Sourcing, é só fazer cada método publicar um evento. A base já está preparada porque o comportamento, e não os dados, está encapsulado aqui."

8. Mapeamento DTO ↔ Entidade — SEM AutoMapper

Decisão consciente: sem AutoMapper. O mapeamento é explícito, fica em um único lugar, e você consegue explicar cada linha na entrevista. A sobrecarga de código é mínima e o ganho de clareza, enorme.

Application/Mappings/SolicitacaoMapper.cs — MAPEAMENTO MANUAL
using VetLab.Application.DTOs;
using VetLab.Domain.Aggregates.SolicitacaoExame;
using VetLab.Domain.ValueObjects;

namespace VetLab.Application.Mappings;

// Classe estática — pura, sem dependências, fácil de testar
public static class SolicitacaoMapper
{
    // DTO (entrada) → Entidade de domínio
    public static SolicitacaoExame ParaEntidade(CriarSolicitacaoDto dto)
    {
        // Converte strings para enums — aqui é o lugar certo para validar/traduzir
        if (!Enum.TryParse<TipoAmostra>(dto.TipoAmostra, ignoreCase: true, out var tipoAmostra))
            throw new ArgumentException($"Tipo de amostra inválido: {dto.TipoAmostra}. " +
                $"Válidos: {string.Join(", ", Enum.GetNames<TipoAmostra>())}");

        if (!Enum.TryParse<TipoExame>(dto.TipoExame, ignoreCase: true, out var tipoExame))
            throw new ArgumentException($"Tipo de exame inválido: {dto.TipoExame}. " +
                $"Válidos: {string.Join(", ", Enum.GetNames<TipoExame>())}");

        // Crmv é value object — sua própria validação roda no construtor
        var crmv = new Crmv(dto.Crmv);

        return new SolicitacaoExame(
            dto.NomeVeterinario, crmv, dto.NomeAnimal, dto.Especie,
            dto.Sintomas, dto.SuspeitaClinica, tipoAmostra, tipoExame, dto.InstrucoesColeta);
    }

    // Entidade → DTO de resposta (saída para API)
    public static SolicitacaoResponseDto ParaDto(SolicitacaoExame entidade)
    {
        return new SolicitacaoResponseDto(
            entidade.Id,
            entidade.NomeVeterinario,
            entidade.Crmv.Valor,
            entidade.NomeAnimal,
            entidade.Especie,
            entidade.SuspeitaClinica,
            entidade.TipoAmostra.ToString(),
            entidade.TipoExame.ToString(),
            entidade.Status.ToString(),
            entidade.JustificativaRejeicao,
            entidade.DataCriacao,
            entidade.DataAtualizacao
        );
    }

    // Lista — LINQ direto, sem mágica
    public static IEnumerable<SolicitacaoResponseDto> ParaDto(IEnumerable<SolicitacaoExame> entidades)
        => entidades.Select(ParaDto);
}
Application/Services/SolicitacaoService.cs — orquestração
using VetLab.Application.DTOs;
using VetLab.Application.Interfaces;
using VetLab.Application.Mappings;
using VetLab.Domain.Aggregates.SolicitacaoExame;
using VetLab.Domain.Exceptions;

namespace VetLab.Application.Services;

public class SolicitacaoService : ISolicitacaoService
{
    private readonly ISolicitacaoRepository _repository;

    // Injeção de dependência — só depende de abstração (interface)
    public SolicitacaoService(ISolicitacaoRepository repository)
    {
        _repository = repository;
    }

    public async Task<SolicitacaoResponseDto> CriarAsync(CriarSolicitacaoDto dto, CancellationToken ct = default)
    {
        // 1. Mapeia DTO → entidade (validações de domínio rodam aqui)
        var entidade = SolicitacaoMapper.ParaEntidade(dto);

        // 2. Persiste
        await _repository.AdicionarAsync(entidade, ct);

        // 3. Mapeia entidade → DTO de resposta
        return SolicitacaoMapper.ParaDto(entidade);
    }

    public async Task<SolicitacaoResponseDto?> ObterPorIdAsync(Guid id, CancellationToken ct = default)
    {
        var entidade = await _repository.ObterPorIdAsync(id, ct);
        return entidade is null ? null : SolicitacaoMapper.ParaDto(entidade);
    }

    public async Task<IEnumerable<SolicitacaoResponseDto>> ListarPorStatusAsync(string? status, CancellationToken ct = default)
    {
        StatusSolicitacao? statusFiltrado = null;
        if (!string.IsNullOrWhiteSpace(status))
        {
            if (!Enum.TryParse<StatusSolicitacao>(status, ignoreCase: true, out var parsed))
                throw new DomainException($"Status inválido: {status}");
            statusFiltrado = parsed;
        }
        var entidades = await _repository.ListarAsync(statusFiltrado, ct);
        return SolicitacaoMapper.ParaDto(entidades);
    }

    public async Task<SolicitacaoResponseDto> AtualizarStatusAsync(Guid id, AtualizarStatusDto dto, CancellationToken ct = default)
    {
        var entidade = await _repository.ObterPorIdAsync(id, ct)
            ?? throw new DomainException($"Solicitação {id} não encontrada.");

        if (!Enum.TryParse<StatusSolicitacao>(dto.Status, ignoreCase: true, out var novoStatus))
            throw new DomainException($"Status inválido: {dto.Status}");

        // Dispara a transição de estado no domínio — regras de negócio aplicam-se
        switch (novoStatus)
        {
            case StatusSolicitacao.EM_PROCESSAMENTO: entidade.IniciarProcessamento(); break;
            case StatusSolicitacao.EM_ANALISE:       entidade.EnviarParaAnalise(); break;
            case StatusSolicitacao.CONCLUIDO:        entidade.Concluir(dto.Laudo!); break;
            case StatusSolicitacao.REJEITADO:        entidade.Rejeitar(dto.Justificativa!); break;
            default:
                throw new DomainException($"Transição para {novoStatus} não permitida via API.");
        }

        await _repository.SalvarAlteracoesAsync(ct);
        return SolicitacaoMapper.ParaDto(entidade);
    }
}

"Por que sem AutoMapper? Três motivos: primeiro, em entrevista você não fica na dependência de 'a biblioteca faz'. Segundo, o mapeamento aqui tem lógica — conversão de string para enum, construção de value object — AutoMapper deixaria isso espalhado. Terceiro, é código simples, estático, testável. Se o projeto crescer e o mapeamento ficar repetitivo, eu introduzo uma biblioteca — mas só quando a dor justificar. YAGNI."

using Microsoft.EntityFrameworkCore;
using VetLab.Application.Interfaces;
using VetLab.Domain.Aggregates.SolicitacaoExame;
using VetLab.Infrastructure.Contexts;

namespace VetLab.Infrastructure.Repositories;

public class SolicitacaoRepository : ISolicitacaoRepository
{
    private readonly ProdutoDbContext _ctx;

    public SolicitacaoRepository(ProdutoDbContext ctx)
    {
        _ctx = ctx;
    }

    public async Task AdicionarAsync(SolicitacaoExame solicitacao, CancellationToken ct = default)
    {
        await _ctx.SolicitacoesExame.AddAsync(solicitacao, ct);
        await _ctx.SaveChangesAsync(ct);
    }

    public async Task<SolicitacaoExame?> ObterPorIdAsync(Guid id, CancellationToken ct = default)
    {
        // Tracking ligado — essa entidade pode ser alterada (AtualizarStatus)
        return await _ctx.SolicitacoesExame
            .FirstOrDefaultAsync(s => s.Id == id, ct);
    }

    public async Task<IEnumerable<SolicitacaoExame>> ListarAsync(StatusSolicitacao? status, CancellationToken ct = default)
    {
        // Query LINQ composável — IQueryable. Filtro só aplica se status vier.
        var query = _ctx.SolicitacoesExame.AsNoTracking().AsQueryable();

        if (status.HasValue)
            query = query.Where(s => s.Status == status.Value);

        // Pronto para paginação: .Skip((pagina-1)*tamanho).Take(tamanho)
        return await query
            .OrderByDescending(s => s.DataCriacao)
            .Take(100) // limite temporário — remover quando paginação existir
            .ToListAsync(ct);
    }

    public async Task SalvarAlteracoesAsync(CancellationToken ct = default)
    {
        await _ctx.SaveChangesAsync(ct);
    }
}

10. Endpoints via Extensions (Minimal APIs + MapGroup)

Aqui está o padrão que você vai explicar no vídeo: em vez de Controllers com herança e [ApiController], usamos Minimal APIs agrupadas por domínio através de Extension Methods sobre IEndpointRouteBuilder. O Program.cs fica limpo — uma linha por domínio.

Api/Endpoints/SolicitacaoEndpoints.cs
using Microsoft.AspNetCore.Mvc;
using VetLab.Application.DTOs;
using VetLab.Application.Services;
using VetLab.Domain.Exceptions;

namespace VetLab.Api.Endpoints;

public static class SolicitacaoEndpoints
{
    // Extension method — this IEndpointRouteBuilder app
    public static void MapSolicitacaoEndpoints(this IEndpointRouteBuilder app)
    {
        // Agrupa todas as rotas deste domínio com prefixo e tag (Swagger)
        var grupo = app.MapGroup("/api/solicitacoes")
                       .WithTags("Solicitações de Exame")
                       .WithOpenApi();

        // POST — endpoint de escrita (grava no banco)
        grupo.MapPost("/", async (
            [FromBody] CriarSolicitacaoDto dto,
            ISolicitacaoService service,
            CancellationToken ct) =>
        {
            var resultado = await service.CriarAsync(dto, ct);
            return Results.Created($"/api/solicitacoes/{resultado.Id}", resultado);
        })
        .WithName("CriarSolicitacao")
        .Produces<SolicitacaoResponseDto>(StatusCodes.Status201Created)
        .Produces(StatusCodes.Status400BadRequest);

        // GET por ID — endpoint de leitura (consulta status)
        grupo.MapGet("/{id:guid}", async (
            Guid id,
            ISolicitacaoService service,
            CancellationToken ct) =>
        {
            var resultado = await service.ObterPorIdAsync(id, ct);
            return resultado is null
                ? Results.NotFound(new { mensagem = $"Solicitação {id} não encontrada." })
                : Results.Ok(resultado);
        })
        .WithName("ObterSolicitacao")
        .Produces<SolicitacaoResponseDto>(StatusCodes.Status200OK)
        .Produces(StatusCodes.Status404NotFound);

        // GET listar com filtro de status
        grupo.MapGet("/", async (
            [FromQuery] string? status,
            ISolicitacaoService service,
            CancellationToken ct) =>
        {
            var resultados = await service.ListarPorStatusAsync(status, ct);
            return Results.Ok(resultados);
        })
        .WithName("ListarSolicitacoes");

        // PATCH — atualizar status (transição de estado)
        grupo.MapPatch("/{id:guid}/status", async (
            Guid id,
            [FromBody] AtualizarStatusDto dto,
            ISolicitacaoService service,
            CancellationToken ct) =>
        {
            var resultado = await service.AtualizarStatusAsync(id, dto, ct);
            return Results.Ok(resultado);
        })
        .WithName("AtualizarStatus")
        .Produces<SolicitacaoResponseDto>(StatusCodes.Status200OK)
        .Produces(StatusCodes.Status404NotFound)
        .Produces(StatusCodes.Status400BadRequest);
    }
}

11. Autenticação — ASP.NET Core Identity (schema auth)

Api/Endpoints/AuthEndpoints.cs — registro/login/JWT
using System.IdentityModel.Tokens.Jwt;
using System.Security.Claims;
using System.Text;
using Microsoft.AspNetCore.Identity;
using Microsoft.AspNetCore.Mvc;
using Microsoft.IdentityModel.Tokens;

namespace VetLab.Api.Endpoints;

public record RegisterDto(string Email, string Password, string Nome);
public record LoginDto(string Email, string Password);

public static class AuthEndpoints
{
    public static void MapAuthEndpoints(this IEndpointRouteBuilder app)
    {
        var grupo = app.MapGroup("/api/auth").WithTags("Autenticação").WithOpenApi();

        grupo.MapPost("/register", async (
            [FromBody] RegisterDto dto,
            UserManager<IdentityUser> userManager,
            CancellationToken ct) =>
        {
            var user = new IdentityUser { UserName = dto.Email, Email = dto.Email };
            var result = await userManager.CreateAsync(user, dto.Password);
            if (!result.Succeeded)
                return Results.BadRequest(new { erros = result.Errors.Select(e => e.Description) });
            return Results.Created($"/api/auth/{user.Id}", new { user.Id, user.Email });
        });

        grupo.MapPost("/login", async (
            [FromBody] LoginDto dto,
            UserManager<IdentityUser> userManager,
            IConfiguration config,
            CancellationToken ct) =>
        {
            var user = await userManager.FindByEmailAsync(dto.Email);
            if (user is null || !await userManager.CheckPasswordAsync(user, dto.Password))
                return Results.Unauthorized();

            var token = GerarJwt(user, config);
            return Results.Ok(new { token = new JwtSecurityTokenHandler().WriteToken(token), validade = token.ValidTo });
        });
    }

    private static JwtSecurityToken GerarJwt(IdentityUser user, IConfiguration config)
    {
        var claims = new[]
        {
            new Claim(ClaimTypes.NameIdentifier, user.Id),
            new Claim(ClaimTypes.Email, user.Email!),
        };
        var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(config["Jwt:Key"]!));
        return new JwtSecurityToken(
            issuer: config["Jwt:Issuer"],
            audience: config["Jwt:Audience"],
            claims: claims,
            expires: DateTime.UtcNow.AddMinutes(double.Parse(config["Jwt:ExpiresInMinutes"]!)),
            signingCredentials: new SigningCredentials(key, SecurityAlgorithms.HmacSha256));
    }
}

Para proteger endpoints: adicione builder.Services.AddAuthentication().AddJwtBearer(...) e chame app.UseAuthentication().UseAuthorization(); Depois, no grupo de endpoints: grupo.RequireAuthorization(); — uma linha protege todo o domínio.

12. Tratamento de Erros & Validação + Delegação ao OpenCode

Api/Middleware/ExceptionMiddleware.cs — global, ProblemDetails
using System.Net;
using System.Text.Json;
using VetLab.Domain.Exceptions;

namespace VetLab.Api.Middleware;

// Middleware global — captura qualquer exceção não tratada e devolve ProblemDetails (RFC 7807)
public class ExceptionMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<ExceptionMiddleware> _logger;

    public ExceptionMiddleware(RequestDelegate next, ILogger<ExceptionMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (DomainException ex)
        {
            // Regra de negócio violada — 400 com mensagem clara
            _logger.LogWarning(ex, "Regra de domínio violada: {Mensagem}", ex.Message);
            await EscreverErroAsync(context, HttpStatusCode.BadRequest, "Violação de regra de negócio", ex.Message);
        }
        catch (ArgumentException ex)
        {
            await EscreverErroAsync(context, HttpStatusCode.BadRequest, "Requisição inválida", ex.Message);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Erro inesperado");
            await EscreverErroAsync(context, HttpStatusCode.InternalServerError, "Erro interno",
                "Ocorreu um erro inesperado. Tente novamente mais tarde.");
        }
    }

    private static async Task EscreverErroAsync(HttpContext ctx, HttpStatusCode status, string titulo, string detalhe)
    {
        ctx.Response.ContentType = "application/problem+json";
        ctx.Response.StatusCode = (int)status;
        var problem = new
        {
            type = "https://httpstatuses.com/" + (int)status,
            title = titulo,
            status = (int)status,
            detail = detalhe,
            instance = ctx.Request.Path
        };
        await ctx.Response.WriteAsync(JsonSerializer.Serialize(problem));
    }
}

// Cliente HTTP único — intercepta e injeta Bearer token, trata 401
const BASE_URL = import.meta.env.VITE_API_URL ?? "http://localhost:5000";

export async function apiClient<T>(
  path: string,
  options: RequestInit = {}
): Promise<T> {
  const token = localStorage.getItem("vetlab_token");
  const headers: Record<string, string> = {
    "Content-Type": "application/json",
    ...(options.headers as Record<string, string>),
  };
  if (token) headers["Authorization"] = `Bearer ${token}`;

  const res = await fetch(`${BASE_URL}${path}`, { ...options, headers });

  if (res.status === 401) {
    localStorage.removeItem("vetlab_token");
    window.location.href = "/login";
    throw new Error("Sessão expirada");
  }
  if (!res.ok) {
    const err = await res.json().catch(() => ({ detail: res.statusText }));
    throw new Error(err.detail ?? `Erro ${res.status}`);
  }
  return res.json() as Promise<T>;
}

14. TanStack Router — Rotas Tipadas

Substitui o React Router. Rotas definidas como árvore tipada — params e search params são inferidos em TypeScript. Menos bugs de rota quebrada.

app/router.tsx — definição das rotas
import { createRouter, createRootRoute, createRoute, Outlet, Link } from "@tanstack/react-router";
import { AuthProvider, useAuth } from "../features/auth/context/AuthContext";

// Layout raiz
const rootRoute = createRootRoute({
  component: () => (
    <AuthProvider>
      <div className="app-shell">
        <Outlet />
      </div>
    </AuthProvider>
  ),
});

// Página de login (pública)
const loginRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: "/login",
  component: () => import("../routes/login.lazy").then((m) => m.default),
});

// Rota protegida — wrapper que verifica autenticação
function Protected({ children }: { children: React.ReactNode }) {
  const { isAuthenticated } = useAuth();
  if (!isAuthenticated) {
    return <Link to="/login">Redirecionando...</Link>;
  }
  return <>{children}</>;
}

// Dashboard (protegida)
const dashboardRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: "/",
  component: () => (
    <Protected>
      {import("../routes/dashboard.lazy").then((m) => m.default)}
    </Protected>
  ),
});

// Detalhe da solicitação — param tipado: $id
const solicitacaoRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: "/solicitacao/$id",
  component: () => import("../routes/solicitacao.$id.lazy").then((m) => m.default),
});

const routeTree = rootRoute.addChildren([loginRoute, dashboardRoute, solicitacaoRoute]);
export const router = createRouter({ routeTree });

// No main.tsx: <RouterProvider router={router} />

"TanStack Router: a grande vantagem é o type-safety de ponta a ponta. Quando você navega com <Link to="/solicitacao/$id" params={{id}} />, o TypeScript cobra o param certo. Search params também são tipados. Em entrevista, eu comparo: React Router é mais conhecido, mas TanStack Router é mais seguro e se integra melhor com TanStack Query (que eu também uso para cache de servidor). Mostrar que você conhece alternativas modernas pesa."

17. Próximos Passos — Para Onde a Arquitetura Evolui

CQRS

Separar escrita (comandos) de leitura (queries). Leitura pode ir para um banco otimizado (read model). Os contextos já estão separados — é só dividir.

Event Sourcing

Cada método do agregado (IniciarProcessamento, Concluir...) publica um evento. O histórico completo da solicitação fica armazenado — auditoria nativa.

Filas & Escala

RabbitMQ/Kafka para processamento assíncrono. Quando milhares de solicitações chegarem, o endpoint de escrita só enfileira — o processamento acontece depois.

Frase de fechamento para a entrevista: "Eu não construí um sistema que resolve o problema de hoje. Construí uma base que, a cada decisão, pensou no problema de amanhã. E isso se prova porque cada camada depende de abstração — eu troco a implementação sem tocar no domínio."
